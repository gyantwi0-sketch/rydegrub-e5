# Browser response security headers (#18)

## Overview
The global `next.config.mjs` rule sends nosniff, HSTS, X-Frame-Options: DENY, restrictive camera/microphone/geolocation Permissions-Policy, Cross-Origin-Opener-Policy: same-origin, Cross-Origin-Resource-Policy: same-origin, Referrer-Policy, and a restrictive fallback CSP. Document responses also use `proxy.ts` to generate a fresh 128-bit cryptographic nonce per response, setting the CSP on **both the upstream Next request and the browser response**. The root layout calls `headers()` so that Next.js dynamically renders nonce-aware hydration scripts. The document policy allows scripts only from their valid nonce/strict-dynamic chain and explicitly denies object embedding, frames, and mixed-content requests. API endpoints do not rely on proxy for access control; the server independently checks JWT/Origin/ownership as required.

Global fallback `script-src 'self'` protects assets, API responses and routes excluded from document middleware. The nonce policy covers document routes excluding Next static assets, images, icons and prefetch requests. **Do not** convert the root document back to statically pre-rendered HTML: it would reuse scripts without a fresh nonce. Reassess caching and nonce coverage whenever new page routes, embedded widgets or external providers are added.

Styles retain `'unsafe-inline'` for compatibility with Next/Tailwind and component inline CSS. This is a deliberate lesser restriction than the script policy, not an XSS waiver. Analytics sources are explicitly allowed in `connect-src`, while any production third-party script still needs a valid nonce as part of the Next hydration chain. New external resources must be reviewed before amending the allowlist. Development HMR permits `'unsafe-eval'` and local WebSocket connections, but production disallows them. CSP, CORP and COOP are not substitutes for route authorization or input validation. COEP is intentionally **not** enabled because third-party analytics/images could stop working without cross-origin resource support.

## Verification and rollout

Run `pnpm lint`, `pnpm test`, `pnpm typecheck` and `pnpm build`. The new Node tests assert nonce production/development policies, static fallback headers, and proxy/layout wiring. Before production deploy, conduct an **HTTPS browser smoke test** with the actual hosting provider: verify the document CSP response header, nonce-bearing Next scripts, hydration, client navigation, images, forms, modal dialogs, analytics and SMS/profile flows in the browser DevTools console. Also test 404/500 responses, API caching headers, prefetch and preview environments. Document CSP failures privately without storing passenger data, OTPs, PNRs, cookies, or credentials. If third-party script load behavior differs in your deployment, investigate its nonce propagation rather than inserting `'unsafe-inline'` or `'unsafe-eval'` into production `script-src`.

A successful CI build demonstrates Next compilation but cannot certify real deployment headers, browser CSP behavior, ingress overrides or Vercel preview status. Deployment smoke tests must be completed before security signoff.
